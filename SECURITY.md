# Security Policy

## Supported versions

Security updates are provided only for the latest minor release line.
See [`VERSION`](VERSION) and [GitHub Releases](https://github.com/gibboda/gentoo-um890pro/releases).

| Version | Supported          |
| ------- | ------------------ |
| 1.3.x   | :white_check_mark: |
| < 1.3   | :x:                |

Older lines do not receive security updates. Please upgrade to the current supported line.

## Scope

This project is a root, disk-wiping Gentoo bootstrap installer for a specific Minisforum machine. Reports should concern the installer and the configuration it generates, not upstream software.

**In scope**

- Confirmation bypass around `WIPE-AND-INSTALL` or other destructive-action guards
- Credential handling (root/user passwords in logs, environment, or process listings)
- Insecure defaults generated by the installer (SSH, sudo, world-writable scripts or units)
- Unverified or insecure downloads of bootstrap artifacts (stage3, signatures, checksums)
- Privilege issues in installer-generated OpenRC/systemd units or helper scripts

**Out of scope**

- Intended data destruction after exact confirmation
- Running the installer as root (required by design)
- Upstream Gentoo, kernel, firmware, live-ISO, or third-party package CVEs (report those upstream)
- Hardware, BIOS, or issues in ROCm/AI stacks unless the installer introduced them

## Reporting a vulnerability

Do **not** open a public GitHub issue for security vulnerabilities.

Report privately using one of these channels:

1. **GitHub private vulnerability reporting** (preferred):
   [Open a private advisory](https://github.com/gibboda/gentoo-um890pro/security/advisories/new)
2. **Email** (fallback only; unencrypted): [gibboda@outlook.com](mailto:gibboda@outlook.com)

GitHub private reporting is preferred because it is encrypted and tracked. Do not send secrets, passwords, or keys over email if a private advisory is an option.

### What to include

- Installer version from `VERSION` or the script header, and git SHA if unreleased
- `INSTALL_PROFILE` and init system, if relevant
- Whether this was a live install or a sourced-function test
- Impact (data loss, privilege, secret leak, supply chain)
- Minimal reproduction steps **on your own hardware**

Do not send a proof of concept that targets anyone else's machine.

### Already public

If a vulnerability is already public, still use the private channel rather than opening another issue. Maintainers will treat it as already disclosed.

## Process

- **Acknowledgement:** within 7 days
- **Initial triage:** within 14 days
- **Fix:** developed privately and shipped on the current minor line when accepted; no backports to unsupported lines
- **Disclosure:** coordinated when possible, typically with a GitHub Security Advisory after a fix is available
- **Declined reports:** you will be told why

There is no bug bounty. Credit in the advisory or changelog is available on request.

## Safe harbor

Good-faith security research against your own disks and systems is welcome. Do not test against systems you do not own or have explicit permission to use.

## Project security posture

Installer scripts are linted with ShellCheck in CI. The repository also uses Snyk; see the README for scan exclusions. These checks do not replace private vulnerability reports.
